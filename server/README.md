# 远程设置服务端

给长辈助手的「子女端远程设置」用。协议见 [`docs/remote-config-protocol.md`](../docs/remote-config-protocol.md)。

**两套实现，同一套协议、同一份控制台页面**，挑一个部署就行：

| | Workers | Node（NAS） |
|---|---|---|
| 适合 | 默认选择，家里没有常开设备 | 想自己攥着数据、家里有 NAS / 树莓派 / 常开电脑 |
| 可达性 | 云厂商保证 | 依赖家里的电和网 |
| 成本 | 免费额度够用 | 0 元（硬件已有） |

---

## 方案 A：Cloudflare Workers

```bash
npm i -g wrangler
wrangler login
cd server
wrangler kv namespace create ELDER
# 把输出里的 id 填进 wrangler.toml 的 kv_namespaces
wrangler deploy
```

部署完得到一个 `https://elder-remote.<你的账号>.workers.dev`，这就是**服务地址**。

国内访问 `workers.dev` 有时不稳，建议绑自己的域名（`wrangler.toml` 里 `[[routes]]` 那段，
域名要先托管在 Cloudflare）。

## 方案 B：NAS / 树莓派 + cloudflared

```bash
cd server/node
node server.js            # 默认 127.0.0.1:8787，数据存在 ./data/store.json
```

另开一个窗口把隧道拉起来（**不需要公网 IP，也不需要备案**）：

```bash
cloudflared tunnel --url http://127.0.0.1:8787
# 输出里的 https://xxx.trycloudflare.com 就是服务地址（临时域名，重启会变）
```

想固定域名（推荐，不然每次重开都要去手机上改地址）：

```bash
cloudflared tunnel login
cloudflared tunnel create elder
cloudflared tunnel route dns elder elder.example.com
cloudflared tunnel run --url http://127.0.0.1:8787 elder
```

⚠️ 默认只监听 `127.0.0.1`，**不要改成 `0.0.0.0` 直接怼公网**。要么走 cloudflared，
要么至少放在带 HTTPS 的反向代理后面——管理端只靠家庭码鉴权。

## 家庭码

家庭码就是这户人家的钥匙，出现在 URL 里，也是控制台的唯一凭据。

- 自己选一个 6–12 位的 `A-Z0-9`，直接写在 URL 里用，不需要注册
- **别用 `123456` 这种**。泄露的代价是别人能绑走你的手机、也能下指令
- 想换钥匙：在手机端「解除绑定」→ 换个家庭码 → 重新绑

绑定时服务端会生成一把 token 存进 KV，之后每个请求都用它签 HMAC。重新绑定会**轮换 token**，
所以「换手机」「怀疑泄露」都是重新绑一次。

### 一位长辈，多个子女

把同一个链接 `/a/<家庭码>` 发给几个人就行，**不用给每个人建账号**。
他们看到的是同一份状态和同一份待执行队列，所以不会重复发指令。

代价要知道：

- **不知道是谁改的**：指令只记录「改了什么、什么时候」，不记录人。
- **没法单独取消某一个人的权限**：只能换家庭码，换个码所有人都得重新收藏、老人手机也要重绑。

需要区分「谁能改、谁只能看」的话，那是下一版的事（协议 §6.1）。

### 一位子女，多位长辈

一台长辈手机一个家庭码。控制台页面顶部「我的家庭」可以存多台，点一下就切。
**这份清单存在你自己的浏览器里**（`localStorage`），服务端不知道谁管几台——
所以换浏览器、清缓存、换手机之后要重新加一次。

清单里每台的身份是浏览器生成的 `id`，不是家庭码。因此
**Workers 上的妈妈（码 8888）和 NAS 上的丈母娘（码 8888）可以同时存在**，互不覆盖。
列表第二行显示的「码 · 域名」就是给你区分同码设备的。

## 长辈端怎么绑

1. 这个 App 设成默认桌面
2. 设置 → 高级设置 → 输入管理密码 → **远程设置**
3. 填服务地址 + 家庭码 → 「绑定并同步」

绑完之后就可以把手机还给老人了。**同步搭在「还在吗」每小时一次的闹钟上**，
不用保持界面开着，也不用额外授权。

## 子女端怎么用

浏览器打开 `https://<服务地址>/a/<家庭码>`，比如
`https://elder-remote.abc.workers.dev/a/8F2C3D1E`。打开时这台设备会自动进「我的家庭」清单。

- 顶部「我的家庭」列出所有已添加的长辈手机，**点一下切换**，绿底那行是当前连接的
- 「＋ 添加长辈手机」填地址 + 家庭码，就能把第二台加进来
- 顶部会显示绑定机型、最后同步时间、电量、上次活跃
- 「日常设置」点一下就下发：字号、语音、还在吗、板块顺序、留言
- 「危险操作」（紧急联系人 / 功能块 / 快捷拨号）**需要老人在手机上点「同意」**才生效，
  24 小时不处理自动作废

指令发出去之后，最长约 1 小时才落地。想立刻生效就手动拨一下老人的手机（提醒他回桌面），
或者等下个整点。

> 设备清单只存在当前浏览器。**把这个链接发给另一个子女，他打开后自己加一次就行**，
> 不需要你帮他配什么。

## 自己验证一下

```bash
# 1. 健康检查（仅 Node 版有）
curl http://127.0.0.1:8787/healthz

# 2. 模拟绑定
curl -X POST http://127.0.0.1:8787/b/TEST1234/bind \
  -H 'Content-Type: application/json' \
  -d '{"deviceId":"test","name":"测试机"}'

# 3. 从控制台发一条指令后，再拉一次（需要带签名，最简单是直接看手机端诊断）
curl http://127.0.0.1:8787/a/TEST1234/api/state
```

## 排错

| 现象 | 原因 |
|---|---|
| 手机显示「找不到服务」 | 地址写错、Worker 没部署、隧道没起 |
| 手机显示「绑定已失效」 | 服务端 token 被换过（重新绑过别的手机），重新绑定即可 |
| 控制台一直显示「还没绑定」 | 手机端没点「绑定并同步」，或者家庭码大小写不一致（服务端会自动转大写） |
| 改了设置一小时都没生效 | 手动点一次「立即同步」看诊断里的「最近错误」；确认手机能上网、地址没变 |
| Workers 上指令发完立刻读不到 | KV 是最终一致，等 30–60 秒 |
