## 未接来电桌面提醒：方案探讨（**只讨论，未改代码**）

用户要求先探讨「怎样展示比较合理」，已拍板三项：

1. **形态 = 顶部常驻提醒条**（不要挂断弹窗）。固定插在 `headerRow` 之下、`sectionSos` 之上；
   无未接时 `GONE` 零占位；不参与「首页板块顺序」三区排序。
2. **点大按钮 = 直接回拨最近一个**（多个不同的人时弹最近 3 条选一个）。
3. **为了显示姓名，引导开启「通知使用权」**（`NotificationListenerService`）。

### 技术结论（查证过，决定了实现路线）

- `READ_CALL_LOG` **不可用**：Android 10+ 对非默认电话应用是**硬限制**权限，设置里也勾不上，
  除非把本应用设成「默认电话应用」（会抢来电界面，否决）。→ 不能直接读通话记录。
- 只加 `READ_PHONE_STATE`：能感知「响铃→未接挂断」，但 **Android 9+ 号码字段必须 READ_CALL_LOG**，
  拿不到是谁 → 只能显示「有未接来电」。
- **`NotificationListenerService` 是唯一现实路径**：从电话 App 的未接来电通知里拿名字/号码/时间，
  不需要危险权限、不需要系统角色。代价是家属手动开一次「通知使用权」。

### 已定的行为规格

- 文案：`儿子 来电未接` / `10:32 · 共 2 个未接来电`；陌生号码显示号码；>3 条显示「还有 N 个」。
- 「知道了」= 只消掉这条提醒，**不删通话记录**；自己存一份未接列表（≤3 条），不依赖系统通知是否还在。
- 过期：超过 24 小时自动隐藏。同人 5 分钟内合并计数。
- 语音：每条只念一次「儿子有未接来电」（跟随语音总开关，`spokenIds` 内存去重）。
- 开关：高级设置里「未接来电提醒」+ 通知使用权状态 + 跳转按钮。
- **识别不到就不显示**（宁可没有，不可误报）——所以没开通知使用权时不做 READ_PHONE_STATE 降级。

### 待真机验证的风险

- 各 ROM 电话 App 的未接通知字段不同（EMUI/鸿蒙通常 `CATEGORY_MISSED_CALL` 或 `CATEGORY_CALL` + 正文含「未接」）。
  计划做多重匹配 + 一个**诊断入口**（列出最近收到但未匹配的通知：包名/category/title/text），
  方便按真机实际格式补规则。
- 电话 App 可能把多条聚合成「3 个未接来电」，计数要容错。
- `applySectionOrder()` 会把三个 section 摘下再按序 `addView`，**提醒条必须在每次重排后重新
  `addView` 到 `headerRow` 之后**，否则会被顶到最上面（实现时要盯住）。

## 更正：用户最终选**方案 B（挂断后弹窗）**，并确定了多人形态

> 上面「形态 = 顶部常驻提醒条」已作废，保留作为决策过程记录。实际实现见下。

- 多人展示：**逐行列表，最多 3 行**（不是「一条 + 另有 N 个」）。每行一个人：头像 + 名字 + 时间 +
  右侧绿色回拨按钮；超过 3 个折成「还有 N 个」。
- 触发时机：**回到桌面时检查并弹**（不申请悬浮窗、不常驻占位）。
  实际等价于「挂断后弹」——来电是全屏打断，挂断后系统回到打断前的界面，而长辈手机多数时候就停在桌面。
- 单人形态：一行 + 大「回拨给 XX」/「知道了」；多人形态：列表 + 「全部知道了」。
- 处理掉一个人不关整窗，剩下的继续列着，全部处理完才消失。
- 同一个号码合并计数（同一条通知重复投递不加次数，阈值 3s）。

## 构建方式评估（云端可行性，仅讨论未实施）

- 现状：**纯本地命令行 Gradle**。Gradle 8.5 发行版（wrapper 缓存）+ JBR 21（`C:\Users\ruok\.jdks\jbr-21.0.11`）
  + SDK（`local.properties` 的 `D:\Install_Programs\Android\SDK`）。**未装 Android Studio**，项目也没有 `gradlew` 脚本，
  直接调用 wrapper dists 里的 gradle 可执行文件。无 `signingConfig` → debug 自动用 `~/.android/debug.keystore`。
- 云端可行（纯 Kotlin + 资源，无 NDK、无私有依赖），但当前**不具备条件**：项目**不是 git 仓库**、无 `.gitignore`、
  本机无 `gh`。走 GitHub Actions 需用户提供仓库授权，且代码外传。
- **上云必踩的三个坑**（将来真要做时按这三点改）：
  ① **签名**：云端 runner 每次新生成 debug keystore → 与已装的本地包签名不一致，覆盖安装失败（报「应用未安装」），
     必须把 keystore 固定进 secret；
  ② **版本号**：`version.properties` 是**有状态**的（打包时 +1 写回），CI checkout 无状态 → 每次同号，
     要么用 `run_number` 当 versionCode，要么 workflow 自动回推；
  ③ **`local.properties`** 是 Windows 绝对路径，不能进仓库，CI 用 `ANDROID_HOME`；顺带项目缺 `.gitignore`。
- 用户结论：**只是了解可行性，暂不动手**。现阶段本地构建更快（增量 6–20s vs 云端排队 2–5min）。
