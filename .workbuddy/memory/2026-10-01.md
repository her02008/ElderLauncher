## 小程序口令 / 桌面快捷方式 / 视频号分享链接 三项增强

用户提出三点：① 试试 `#小程序://WorkBuddy/QR4y030Xwq0ycoi` 这种微信 Short Link 分享口令；② 试试「桌面快捷方式 + Intent 跳转」；③ 视频号能否通过分享链接直达。

调研结论：
- `#小程序://` 口令是官方 **Short Link**（generateShortLink 生成），设计为「在微信里点击打开」，外部 App 没有公开 scheme。我们做法：从整段转发文案里正则抠出口令 → 先猜 `weixin://dl/business/?t=<ticket>` 和 `?ticket=` 两种包装拉一次 → 失败退回微信首页 + 提示用户把口令发到任意微信聊天里点。
- 微信自己「添加到桌面」生成的快捷方式 Intent 带 ext_info/digest/token 等设备签名字段（可 `adb shell dumpsys shortcut | grep WX_SHORTCUT` 提取），**无法伪造**，所以走我们自己的 pin shortcut + 中转 Activity。
- 视频号分享链接（channels.weixin.qq.com）：先 `setPackage(com.tencent.mm)` 让微信直接接（部分版本注册了自家 AppLink）→ 失败交给浏览器 H5 中转拉微信 → 再失败退回无障碍自动导航。

代码改动：
- `ActionExecutor.openMiniProgram` 重构为 5 分支（口令 / 视频号链接 / weixin scheme / https / gh_wx@app 包装），新增 `extractPasscode`（公开，供粘贴时复用）、`openPasscode`、`openChannelsLink`。
- 新增 `pinMiniShortcut`（API 26+ `requestPinShortcut`，24/25 走 `INSTALL_SHORTCUT` 广播并 `@Suppress("DEPRECATION")`）、`disableMiniShortcut`（删除项时禁用桌面图标）、`shortcutIcon`（192px 圆形 + 名称首字，配色取 BlockCatalog.palette 按 name.hashCode() 取色）、`miniShortcutId`（`"mini_" + target.hashCode()` hex，稳定可反查）。
- 新增 `MiniShortcutActivity`（透明中转页，继承 **android.app.Activity** 而非 AppCompatActivity——AppCompat 主题校验下不能用 `Theme.Translucent.NoTitleBar`；excludeFromRecents + noHistory）。
- `WxMiniActivity`：粘贴时若剪贴板含口令则只填口令且**自动带出名称**（口令第二段，截 12 字）；编辑弹窗新增「添加到桌面」按钮；删除时禁用对应桌面图标。
- Manifest：`INSTALL_SHORTCUT` 权限（maxSdkVersion=25）+ MiniShortcutActivity 注册。
- strings：`wx_mini_shortcut_*`、`wx_mini_passcode_fallback`、`wx_mini_removed`；`wx_mini_target_hint` 更新。

坑：
- `ShortcutManager` 在 **android.content.pm**，不是 android.app（编译报 Unresolved 才发现）。
- 两个 Gradle 构建并发跑会导致 Kotlin 增量缓存损坏（`lookups.tab.values.s does not exist`）→ `gradle --stop` + 删 `app/build/kotlin` 后重编即好。

`assembleDebug` 通过，0 error / 0 warning，APK 7.0M。

## 推倒重来：改为「调用微信自己创建的桌面快捷方式」

用户澄清：上一版自造「添加到桌面」理解错了，他的想法是**利用微信小程序自带的「添加到桌面」**——
先让用户在微信里把小程序快捷方式发到系统桌面，本项目再调用这些创建好的快捷方式，间接直达小程序。

**清理**（自造快捷方式功能全删）：
- `ActionExecutor`：pinMiniShortcut / installShortcutLegacy / disableMiniShortcut / shortcutIcon / miniShortcutId 全删；
- `MiniShortcutActivity.kt` 删除；Manifest 删 MiniShortcutActivity + `INSTALL_SHORTCUT` 权限；
- `dialog_edit_mini.xml` 删 btnShortcut；`WxMiniActivity` 删按钮逻辑与 disableMiniShortcut 调用；
- strings 删 `wx_mini_shortcut_*`、`wx_mini_removed`（注意 `wx_mini_passcode_fallback` 还在用，别误删）。

**新实现** `util/WxShortcuts.kt`：
- 本项目是默认桌面（HOME+DEFAULT）→ 系统放行 `LauncherApps` 枚举 `com.tencent.mm` 的
  `FLAG_MATCH_PINNED` 快捷方式 → `LauncherApps.startShortcut(info, null, null)` **原样启动**，
  微信侧签名校验由系统/微信自己完成，间接直达小程序。
- 快捷方式在本项目的身份编码：`wxshortcut://<shortcutId>`，存在 `HomeBlock.pkg` /
  `WxMiniApp.target` 都行，`openMiniProgram` 新增第 0 分支路由到这里；启动失败（快捷方式被删/不是默认桌面）
  → toast `wx_shortcut_missing` + 开微信首页。
- 坑：`ShortcutQuery` 没有公共 `queryFlags` 字段（要用 `setQueryFlags()`）；API 34 SDK 里
  **没有** `getShortcuts(query)` 单参重载（文档上 API 33 加的那个实际不存在/不同名），
  只能用两参 `getShortcuts(query, user)`（33+ 弃用 → `@Suppress("DEPRECATION")`）。
- 接入点：① `HomeBlocksActivity.pickMinis()` 把微信 pinned 快捷方式追加进多选列表（key = wxshortcut://id，
  按 key 去重）；② `MainActivity.openMiniPrograms()` 同样追加，唯一入口为 1 个时直接打开。
- 限制：快捷方式读取**要求本项目是默认桌面**（不是则返回空列表，各处自然降级为只用手工配置项）。

## 快捷拨号重启才生效 + 鸿蒙4 注册桌面

1. **快捷拨号添加后主页不实时刷新（真 bug，已修）**：`MainActivity.setupQuick()` 把 `quickList`
   实例直接传给 `QuickContactAdapter`（adapter.items === quickList），而 `applyQuickList` 里
   `quickAdapter.update(quickList)` 传了同一个实例——`update()` 内部 `items.clear()` 把 quickList
   也清空，再 `addAll(quickList)`（已是空列表）等于什么都没加 → 主页快捷拨号被清空，直到重启
   `onCreate` 重新解析才恢复，表现为「添加成功但重启才生效」。修法：`applyQuickList` 里给
   `update()` 传**外部传入的 newList**（不同实例），quickList 自己 clear/addAll 同步内容。
   **教训：任何「adapter 持有外部 list 实例 + update(list)」的组合，绝不能把 holder 的那份 list
   原样传回 update，必须传另一份实例。**
2. **鸿蒙 4 无法注册为手机桌面**：曾改为 `RoleManager.createRequestRoleIntent(ROLE_HOME)` 弹系统
   角色确认框——**真机反馈按钮直接没反应**（弹窗 Intent 发出后界面不出现，静默失败），已回退为
   直接 `openHomeSettings()`（ACTION_HOME_SETTINGS，鸿蒙 4 实测能跳转）。**结论：鸿蒙 4 上别用
   RoleManager 弹窗，只能跳设置页。**用户反馈的另一半「默认桌面列表里不出现本工具」属于 ROM 侧
   限制：最常见原因是鸿蒙「纯净模式」把侧载 App 挡在默认应用候选外（关纯净模式或经应用市场装），
   少数情况要重启一次手机再进 设置→应用和服务→默认应用→桌面。Manifest 的 MAIN+HOME+DEFAULT
   过滤器本身是标准的，无需改。

## 视频号链接直达：加自带 WebView 中转页，省掉系统浏览器一步

用户反馈：链接路径可行，但中途要打开系统浏览器再点一次「打开微信」才能进微信，要求省掉/简化。

实现：新增 `ChannelsBridgeActivity`（透明 WebView 中转页，插在「微信直连」与「浏览器兜底」之间）：
- `shouldOverrideUrlLoading` 拦 `weixin://` 直拉微信、`intent://` 且 scheme=weixin 的还原成 `weixin://` 后拉起；
- `onPageFinished` 后注入 JS：先点 `a[href^="weixin://"]`，否则按关键词（打开微信/前往微信/微信中打开/继续访问/打开小程序）点按钮，没找到 900ms 重试；
- 4s 无动静亮出「打不开？再试一次」大按钮；12s 仍无动静 → toast 后 `openChannels()`（无障碍自动导航）并 finish；
- 非 weixin.qq.com 的 http(s) 外部链接交浏览器。
- `tryOpenChannelsLink` 顺序变为：微信 setPackage 直连 → **本中转页** → 浏览器兜底 → false。

注意：
- 本 App 之前没有 INTERNET 权限，本次已加（WebView 必须）。
- 透明主题 Activity 继承 `android.app.Activity`（同 MiniShortcutActivity 教训）。
- JS 注入用 evaluateJavascript 返回值判断是否点中；`launching` 标志防重复拉起。

## 视频号：中转页改为「完全隐形跳板」+ 主页优先用链接（修 3 个问题）

用户反馈三点：① 链接直达能看视频但**不能上下滑切换、返回直接退出**；② 设置好链接后主页仍弹无障碍提示；③ 逻辑应为「设了链接就直接打开链接」。

根因与修复：
1. **在自家 WebView 里看视频** = 普通网页播放器，没有视频号的原生上下滑，返回键还会退掉我们这层透明页。
   → `ChannelsBridgeActivity` 重写：WebView 设 `INVISIBLE`（**只当跳板，绝不显示网页内容**），
   页面只留一个深色遮罩 +「正在打开微信…」。握手方式改为**主动从页面里抠 `weixin://`**：
   JS 先找 `a[href^="weixin://"]`，再从 `documentElement.outerHTML` 正则捞
   `weixin://dl/business/...`（优先）或任意 `weixin://xxx`，返回 `U|<url>` 给 Java 侧**原生 startActivity**——
   这绕开了「WebView 拦截非用户手势的自定义 scheme 跳转会被杀」这个坑（之前 JS 点了按钮也拉不起来微信）。
   探针 700ms × 7 轮（约 5s），`onPageFinished` 触发；另加 7s 硬兜底防白屏/断网。
   `intercept()` 现在对 http(s) 一律放行（分享链接有跳转链，拦下来反而拿不到最终 scheme），只拦 `weixin://`。
   失败 → `ActionExecutor.openChannelsFallback()` + finish，不让用户卡在空页面。
2. **主页先判无障碍导致链接没机会用**：`MainActivity` 的 `HomeAction.CHANNELS` 分支原为
   `if (isReady()) openChannels() else promptChannelsAccessibility()`。改为
   `if (hasLink || isReady()) openChannels() else prompt...`（`PrefsManager.getChannelsLink().isNotEmpty()`）。
3. `ActionExecutor` 把兜底路径抽成公开的 **`openChannelsFallback(ctx)`**（无条件跳板的 无障碍→scheme→微信首页），
   `openChannels(ctx)` = 链接 → fallback。分开是为了防止跳板失败后拿着同一条链接再转一圈死循环。

strings：`channels_bridge_waiting`「正在打开微信…」、`channels_bridge_fallback`；旧的 `channels_bridge_retry` 已删除。
`assembleDebug` 通过 0 error / 0 warning。

## 视频号「提示后什么都没打开」：兜底不再静默失败 + 跳板加网

用户反馈：点主页视频号 → 提示「链接没能直开，正在自动进入视频号」→ 什么都没打开。

根因（两个叠加）：
1. **旧的 scheme 试探会静默失败**：`openChannelsFallback` 里 `weixin://channels / channelslive / dl/channels`
   能被 `resolveActivity` 解析到微信，于是 `startActivity` 后直接 `return`——但微信对这类私有 scheme
   一律不响应（真机早已验证），结果是"没报错、也没打开"。**这些 scheme 试探已全部删除**。
2. **微信对外部链接就是不配合**：查证确认视频号分享链接（`channels.weixin.qq.com` / `weixin.qq.com/sph/...`）
   只在微信客户端内有效，外部打开只会提示「请在微信客户端打开」，页面里往往**没有**可用的 `weixin://`。
   所以跳板经常两手空空，必须有个"看得见"的收场。

改动：
- `ActionExecutor.openChannelsFallback(ctx): Boolean`（返回值 = 无障碍是否接管）；`openChannels` = 链接 → 无障碍
  → 最后 `openWeixinHome()` + toast，保证一定有可见动作。**注释里写死"不要再加 scheme 试探"**。
- `ChannelsBridgeActivity` 加两道新网：
  ① `WebChromeClient.onConsoleMessage` 里正则捞 `weixin://`（WebView 拦下非用户手势跳转时会把地址打进控制台
  —— 这是模拟点击拿不到跳转时最有效的一招）；
  ② JS 探针新增**异步 fetch 页面自己的 js/json 资源**（scheme 常藏在打包脚本里，HTML 里搜不到），
  结果缓存到 `window.__wbLink`；按钮点击改为 `dispatchEvent(MouseEvent)` + `click()` 双发。
  超时收紧到 ~4s（6 轮 × 700ms），硬兜底 5s。
- 兜底分流：无障碍**已开** → `openChannelsFallback()` 自动进视频号；无障碍**没开** → 不用 toast 糊弄，
  而是带 `MainActivity.EXTRA_CHANNELS_HINT` 回到桌面弹 `promptChannelsAccessibility()` 引导
  （里面本来就有「去开启 / 只打开微信 / 取消」）。MainActivity 的 `onCreate` 与 `onNewIntent`
  都处理这个 extra（MainActivity 是 singleTask，会走 onNewIntent）。
- 文案：`channels_need_accessibility` 改为说明"微信不接受外部链接直达"；`channels_link_hint` 也加了
  「建议同时开着无障碍服务」这句（链接只是尽力而为，无障碍才是稳定路径）。
`assembleDebug` 通过 0 error / 0 warning，APK 6.2M。
