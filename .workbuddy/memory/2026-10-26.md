## 语音交互 + 「还在吗」详细设计（未实现）

用户提三个需求：语音交互（方言）、子女端远程设置、参考「死了么」的「还在吗」。经确认：
**本轮只出设计，不动代码**；方言走「系统识别 + 拼音容错」；遥控设置下一轮。

设计文档：`docs/design-voice-alive.md`（本仓库，实现时照此执行）。

关键决策与理由（都已写进文档，这里记要点）：

- **语音难点不是识别率，是「识别错了还能对上」**。方案：汉字→拼音（`tinypinyin`）→ 模糊音归一化
  （zh/z、ch/c、sh/s、ing/in、eng/en、n/l）→ 编辑距离打分，阈值 0.62。命令集**封闭 15 条**，不做自由对话。
  命令侧拼音**预计算并手工校对多音字**，识别侧实时转。
- **交互用「点一下说，静音 1.2s 自动停」**，不做按住、不做常驻唤醒词（老人手抖会松手；常驻费电+隐私+方言唤醒词识别差）。
  `EXTRA_MAX_RESULTS=3` 逐候选匹配，命中率明显高于只看第一位。
- **「救命」必须二次确认**：弹红色全屏页 + 3s 倒计时默认执行（老人喊完可能没力气再点），点「我没事」撤销。
  这条取舍要写死在注释里，防止以后被「优化」成直接执行。
- **收音机是硬件问题**：2020 年后大多无 FM 芯片，只能探测包名/Intent，失败必须明确告知，不能静默。
- **「还在吗」不能照搬「死了么」的主动签到**（老人不会签），改被动检测：`ACTION_USER_PRESENT` 解锁 +
  无障碍窗口变化 + App 前台，三源取最新，节流 1 分钟。
- **定时检查必须用 `AlarmManager.setExactAndAllowWhileIdle`**，`WorkManager` 在 Doze 下会推迟几小时到一天，
  「24 小时预警」会变 30 小时。间隔取 1 小时（够精度又省电），Android 12+ 检查 `canScheduleExactAlarms()` 降级，
  触发后自己续排，`BootReceiver` 重排。
- **预警通道用短信不用推送**：`SEND_SMS` 已有（SOS 在用），老人手机没网也能发、子女不用装 App、运营商级可靠。
  为这个功能上整套后端不划算。
- **必须有「暂停 1/3/7 天」**：住院/出远门/手机落家会误报，连续误报几次子女就不信告警了，误报抑制比灵敏度重要。
- **必须有「已恢复」短信**：子女收到预警会一直担心，需要明确的结束信号。
- 预警最多 3 条，二次提醒间隔 12h；恢复活跃清零；首次开启初始化 `lastActive=now`（否则一开就报）。
- **遥控设置本轮零代码**，但已确认不挡路：心跳源（`lastActiveAt`）、配置可序列化（全 JSON）天然可用；
  缺 deviceId、绑定码、审计、下发通道。下一轮三个硬约束：推送是死结（个人做不了厂商通道）→ 走无障碍心跳拉取
  15–30 分钟；子女端做微信小程序；远程改配置等于远程控制，绑定码一次性 + 危险操作老人端可见。

## 实现：语音交互 + 「还在吗」（v1.0.25 / 构建 26）

`assembleDebug` 通过 **0 error / 0 warning**，APK 6.44M。

### 语音

- **拼音库换成系统 ICU**：`tinypinyin:2.0.3` 在 mavenCentral **拉不到**（`FAILED`），已删依赖。
  改用 `android.icu.text.Transliterator`（API 24 起自带）：`Han-Latin` 普通读音、`Han-Latin/Names` 人名读音。
  **逐字转换**（不是整串），保证音节边界，`fold()` 才能按音节做 n→l / 前后鼻音，不会误伤 an/en/in 的韵尾。
  `ü` 在 NFD 去调时特判成 `v`，否则「女/努」都变 nu 撞车。ICU 不可用时降级为保留原文（功能退化但不崩）。
- **算法用 Python 模拟验过**（阈值 0.62）：正样本 0.78（打电发/打电话）、0.95（收银机/收音机，平翘舌合并后相等）；
  负样本 0.21~0.28。两侧余量都够，阈值不用调。
- `VoiceCommandMatcher.matchOne` 的顺序**不能改**：
  ① `extractCallName` 先跑（否则「打电话给儿子」会被 CALL_PLAIN 的「打电话」以 1.0 抢走，变成开拨号盘）；
  ② 内置命令打分；③ **≥0.9 就直接返回**（否则「打开手电筒」会被 OPEN 抽成目标）；④ 才试 `打开 X`。
- `OPEN_PREFIXES` 长前缀必须在短前缀前（`打开` 在 `开` 前），否则「打开微信」被 `开` 吃掉剩「打微信」。
- 语音页**不 TTS 播报**（MainActivity.onAction 里注释写死）：播报声会被麦克风收进去，老人得等它念完才能说。
- 「救命」→ 全屏红页 + 3 秒倒计时**默认执行**（老人喊完可能没力气再点），取消/返回键可撤销。`sosDialog` 要在 onDestroy dismiss。
- 收音机三级探测（包名 / `action.FM` / 标签含「收音机/广播/FM」），找不到明确说「这台手机没有收音机」。
- 新文件：`util/PinyinMatcher.kt`、`util/VoiceCommand.kt`（枚举+意图+Matcher）、`util/ContactFinder.kt`、
  `util/RadioLauncher.kt`、`VoiceActivity.kt` + `activity_voice.xml` + `dialog_voice_sos.xml`、`ic_mic` 等 4 个 drawable。
- `HomeAction.VOICE` 已进 `ORDER/ICONS/LABELS/COLORS` 四张表，并**加进 defaultBlocks 第一格**
  （老用户有存储不会自动出现，要在功能块管理里自己加）。

### 还在吗

- `util/AliveCenter.kt`（状态/判定/短信/排程）+ `util/SmsSender.kt` + `receiver/AliveAlarmReceiver.kt`。
- 活跃来源三处：无障碍 `onAccessibilityEvent` 开头 `touch()`（在业务 return 之前）、无障碍里动态注册的
  `USER_PRESENT` + `SCREEN_ON`（用 `RECEIVER_EXPORTED`，这两个是 protected broadcast）、主页 onResume。
- **`touch()` 里报过警的必须强制写 lastActive 再 recover**：如果跟着 60 秒节流一起跳过，
  lastActive 还是几十小时前，下一次检查又判超时 → 「恢复/报警」来回横跳。
- `AlarmManager.setExactAndAllowWhileIdle` 1 小时一次，**一次性闹钟必须自己续排**（Receiver 的 finally 里），
  `BootReceiver` 重排。Android 12+ `canScheduleExactAlarms()` 为 false 时降级 `setAndAllowWhileIdle`。
- 自己记 `alive_next_check`（`am.nextAlarmClock` 读不到 setExactAndAllowWhileIdle 排的时间）。
- 阈值 12/24/48，最多 3 条、间隔 12h，恢复发「已恢复」短信，暂停 1/3/7 天。
- **无障碍没开时这个功能基本失效**（只剩打开桌面算活跃），诊断里会显示。
- SEND_SMS 是运行时权限，开启时用 `registerForActivityResult` 当场申请。

## 子女端远程设置：方案探讨（零代码）

用户先问「还有啥实现方式」，再提「子女端起服务端 + 短信下发指令和链接」的设想。结论：**技术上成立**，
架构是「短信做信封与叫醒，HTTP 做货运」，但**子女端入口的"永远可达"才是真难点**，不是"怎么连"。

- 三档方案：**A 无需服务端**（短信口令 / 通知关键字 / 来电叫醒）；**B 轻服务端**（云 KV 心跳拉取 /
  公共 bin 信箱 / 局域网直连）；**C 重通道**（聚合推送、长连接、远程同屏——都不建议，推送只能叫醒不能传数据）。
- **反复强调的结构观点：下发 / 落地 / 回执是三条独立链路**，只做第一条会出现「子女改完不知道生效没」。
  落地段三档共用：命令白名单 → 参数范围校验 → 写 PrefsManager → 老人端可见提示 → 回执。
- **短信的边界**：单条 70 汉字，一个 URL 就 30+ 字符，只够「地址 + 配对码 + 一条短指令」，**不能当持续通道**。
- **可以省掉一半复杂度的事实：绑定只需要一次**。让子女拿老人手机手输一次地址 + 配对码，
  就不必申请 `RECEIVE_SMS`（敏感权限、上架要说明）；此时短信只剩「叫醒」一个用途，
  而叫醒可以用已有的 `AliveAlarmReceiver` 1 小时闹钟代替 → 连短信都能先不做。
- **最强的建议是「协议先行」**：短信里只放地址，长辈端只认协议（`GET /b/{code}/cfg`、`POST /b/{code}/ack`），
  不关心服务跑在哪。今天 Workers、明天自家 NAS + cloudflared，长辈端不用改。服务与存储不能绑死。
- **子女端自建服务器的硬伤**：家宽普遍 NAT + 封 80/443 → 必须隧道（`cloudflared tunnel` 免费、无公网 IP、
  固定域名、不用备案，优于要公网 VPS 的 frp）；**家里停电/断网/设备关机 = 全哑，而"最需要远程"的时刻
  恰恰是子女不在家** → 不适合做产品默认形态，适合有常开设备的家庭。
- **顺带的大收益**：`/ack` 同时上报活跃时间，「还在吗」的短信预警可升级为子女端页面直读，短信留作断网兜底。
- 安全底线（写死）：一次性配对码限时、指令白名单 + 参数范围校验、危险指令（关 SOS / 改紧急联系人 /
  清空色块）老人端必须可见确认不可静默、变更审计、解绑只能老人端操作。

## 实现：子女端远程设置（v1.0.29 / 构建 30）

按用户选定方向落地：**协议先行、服务可换**。`assembleDebug` 0 error / 0 warning，APK 6.2M。

- 契约：`docs/remote-config-protocol.md`（端点、HMAC 签名串、指令白名单、危险指令语义、存储模型）。
- 两套服务端 + 一份控制台：`server/workers/worker.js`（KV）、`server/node/server.js`（零依赖 JSON 文件 +
  原子 rename）、`server/admin.html`（两边共用，worker 用 wrangler Text 模块内嵌）、`server/README.md`。
- **协议用 Node 版跑过 15 条冒烟测试全部通过**（bind/未知 op 拒绝/缺签名 401/rev 去重/danger 标记/
  ack 摘队列/状态快照/不泄露 token/过期时间戳 401/重绑轮换 token/旧 token 失效/管理页 HTML）。
  测试脚本是临时的，没入库。
- Android：`RemoteClient` / `RemoteCenter` / `RemoteCommand` / `ui/RemotePrompt` / `RemoteActivity`，
  入口挂在高级设置的新卡片。同步搭 `AliveAlarmReceiver` 的 1 小时闹钟（goAsync + 后台线程）。
- 踩到的两个坑：
  1. **KDoc 里写 `http://` 会挂**——`//` 后面紧跟 `*` 组成 `/*`，Kotlin 把它当**嵌套注释**的开头，
     之后整份文件都被当注释，报的却是「Missing '}'」。以后注释里别直接写带 `//` 的 URL。
  2. **`org.json.JSONArray` 不是 Iterable**，`queue.any { }` 编译不过，必须按下标 `optJSONObject(i)`。
  3. `applyDanger` 一开始用表达式体 + 分支里 `return`，换成块体才行。
- **设计上补掉的漏洞**：`AliveCenter.schedule()` 原本只判 `isAliveEnabled`，绑了远程却没开「还在吗」的用户
  永远不会有第二次同步。改成「两者任一成立」，并且关「还在吗」时改为调 `schedule()` 而不是 `cancel()`。

### 远程设置 B 档：多设备 + 修并发丢指令（v1.0.30 / 构建 31）

用户问「一个子女能否管多个长辈、多个子女能否管一个长辈」，答完发现现有实现有两个实质问题，
按 B 档落地：

1. **并发丢指令（真 bug）**。原来待执行指令放在 `cfg:{code}.cmds` 数组里，下发是
   「读数组 → push → 写回」，两个子女同时点按钮，双方都读到 `[A]`，各自写回，后写的覆盖先写的。
   Workers 的 KV 还是最终一致的，窗口比想象中大。
   → 改成**一条指令一个键** `cmd:{code}:{id}`，新增 `meta:{code}` 存 `{rev, clearedAt}`。
   ack 直接删键；`clearedAt` 给「清空」做并发兜底（`at <= clearedAt` 的残留视为作废）。
2. **`rev` 量级坑**。想让 rev 在多写者下不撞回旧值，最自然是毫秒时间戳，但长辈端用
   `JSONObject.optInt` 解析，1.7e12 会被截断成负数 → 客户端永远认为版本变了 → 每次同步重跑全部指令。
   → 用 `秒级时间戳 - 1600000000`（约 1.9e8），2038 年也才 5.5e8，安全。
   **这个坑写进协议文档了，别再改回毫秒。**
3. **客户端幂等兜底**：`RemoteCenter.sync()` 执行前跳过「回执队列里已有的 id」。
   回执队列的语义正好就是「已处理但服务端还不知道」，不用新增存储。
   这样即使服务端 rev 抖动、ack 丢包重发，也不会重复执行 `push_msg` / 反复弹危险确认。

子女端 `admin.html` 改成多设备视图：`localStorage['elder_devices']` 存
`[{endpoint, code, alias, reportedName}]`，顶部点一下切换，`/a/CODE` 打开自动入列，
旧的两个键（`elder_endpoint`/`elder_code`）自动迁成一条记录。手机自报的 `bind.name` 会回填，
所以不给备注名也能显示「妈妈的手机」。

**验证方式**：起本地 Node 服务 + 29 条协议断言（含「并发下发 5 条一条不丢」「rev 32 位安全」
「清空后不复活」「重绑不丢未执行指令」）；admin.html 用最小 DOM 桩把真实脚本跑起来，
23 条断言覆盖切换/增删/规范化/名字回填。全过。

### 子女端「识别不同长辈」的三层标识（当晚补的）

用户问子女端怎么区分不同长辈，梳理完发现清单主键选错了，已修：

| 层 | 是什么 | 用途 |
|---|---|---|
| `deviceId` | 长辈手机首次安装生成的 UUID（`PrefsManager.getDeviceId`） | **只**给服务端校验 HMAC 签名，子女端看不到 |
| `code` 家庭码 | 用户自己填的 `[A-Z0-9]{4,16}` | 服务端所有键的前缀（`bind:/meta:/cmd:/state:`），**同一服务端内**唯一 |
| 浏览器清单 `id` | `d_xxxxx`，添加时生成 | 子女端 UI 的主键：切换/删除/落盘 |

**原来的 bug**：`findDevice(code)` / `upsertDevice` 只比 `code`。
`code` 只在单个服务端内唯一，所以「Workers 上的妈妈 8888」和「NAS 上的丈母娘 8888」
会互相覆盖——加第二台时把第一台的 endpoint 改掉，表现为「妈妈那台消失了」。
→ 判重用 `deviceKey(endpoint, code)`（去尾斜杠 + 小写归一），标识/切换/删除一律走 `id`。
老清单（无 id）启动时自动补，老 `ACTIVE`（存的是 code）自动转 id。

顺带修掉一个显示串台：`loadState()` 的响应回来时用户可能已经切了设备，
现在是「回来先比对 ACTIVE 是否还是发起时那台，不是就丢弃」。

### 真机待验（远程设置）

1. Workers 部署后从手机绑定，看 `/a/<码>` 是否能显示机型、同步时间、电量。
2. 改字号 —— 老人回桌面应自动 recreate 生效（复用 `MainActivity.appliedFontSize` 那套）。
3. 改紧急联系人 —— 老人桌面应弹「家人要改一项设置」，点同意后 SOS 号码变了；点不同意则不生效。
4. Worker 的 KV 最终一致性：下指令后立即刷新管理台可能还是旧数据，等 30–60 秒再试。

### 真机待验（还没验过）

1. `Han-Latin` 在你的鸿蒙机上是否可用（不可用会退化成精确匹配，语音仍能用但方言容错没了）——看长按语音页是否……没有诊断入口，只能靠实际识别效果判断。
2. 各家 ROM 的 SpeechRecognizer 是否已选引擎（`isRecognitionAvailable`），没选会提示。
3. 「还在吗」：把阈值设 12 小时、手动改 `alive_last_active` 到 13 小时前，等闹钟或重启验证。
4. 收音机探测结果（很多机型没有 FM）。
