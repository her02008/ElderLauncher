## 第四轮：重置暗号改 `*#0454#*` + 拦截服务码（用户反馈「connection problem or invalid MMI code」）

### 1. 暗号换结尾：`*#0454*#` → `*#0454#*`

- 用户真机输入 `*#0454*#` 后按拨号，弹系统英文报错
  **「connection problem or invalid MMI code」**——因为 `*#...*#` 这种「`*` 开头、`*#` 结尾」的形态
  正是运营商服务码（MMI/USSD）的格式，一旦这一串被交给系统拨号，telephony 就会当指令处理并弹英文报错。
- `AdminGate.RESET_CODE` 改成 **`*#0454#*`**（`*` 开头、`#*` 结尾，不构成 MMI 形态）。
- 老暗号 `*#0454*#` 没丢：放进 `AdminGate.LEGACY_RESET_CODES`，用新加的
  `AdminGate.isResetCode(input)` 统一判定（顺手 strip 空格 / 短横线）。
  `DialActivity.onCall()` 不再直接 `== RESET_CODE`，改调 `isResetCode()`。

### 2. 兜住系统 MMI 报错（这才是症状的根治点）

- `DialActivity.onCall()` 在暗号判定**之后**新增拦截：`typed.startsWith("*") || typed.startsWith("#")`
  → 不拨号，弹 `dial_service_code`（「这是服务指令，不能拨打。请检查号码是否正确」）并 `return`。
- 理由：老人拨号盘只会拨普通号码，`*`/`#` 开头的一定是误按；交给系统只会再弹一次看不懂的英文。
  这样**即使暗号判定因为别的原因漏了，也不会再出现 MMI 报错**（双重保险）。
- 注意顺序不能反：先 `isResetCode()` 再拦 `*`/`#`，否则新老暗号都会被自己拦掉、打不开重置框。
- 文案 `dial_service_code` 新增；`activity_admin.xml` 的 `tvAdminCodeTip` 预览文案（`tools:text`）
  里的暗号同步改成 `*#0454#*`。
- `admin_code_tip` 是 `%1$s` 占位、由 `AdminActivity` 传 `AdminGate.RESET_CODE`，改常量即全站生效，无需动文案。

`assembleDebug` 通过 0 error / 0 warning，本次交付包 **v1.0.4（构建 5）**，APK 6.3M。

## 第七轮：支持「发送到桌面」的桌面快捷方式（微信小程序 / 浏览器 / 别家 App）

用户问：已设为默认 launcher 了，怎么添加桌面快捷方式（微信小程序发送到桌面的、浏览器发送到桌面的）？

**先查清平台契约**（AOSP `ShortcutRequestPinProcessor` + LauncherApps 文档确认）：
- API 26+ 的「添加到桌面」走 `ShortcutManager.requestPinShortcut()`；
- 系统**不自己弹确认框**，而是去**默认桌面**包里找声明
  `android.content.pm.action.CONFIRM_PIN_SHORTCUT` 的 Activity 并拉起，由它自己问用户；
- 找不到 → `getRequestPinConfirmationActivity` 返回 null → 整个请求失败，
  调用方的 `isRequestPinShortcutSupported()` 也是 false，于是点了没任何反应
  （日志 `Launcher doesn't support requestPinnedShortcut(). Shortcut not created.`）。
- 接受后调 `PinItemRequest.accept()`，这条快捷方式归属本 launcher，之后可用
  `LauncherApps.getShortcuts(FLAG_MATCH_PINNED)` 枚举 + `startShortcut` 原样启动。

### 新增 / 改动

- 新增 `ShortcutPinActivity`（+ Manifest 声明 + `Theme.Elder.Translucent` 新样式）：接收 pin 请求，
  弹确认框，接受后加一个 `BlockType.SHORTCUT` 色块到主页。**不设管理密码**（加了就断链，且只加图标）。
- 新增 `util/PinnedShortcuts.kt`（通用 `shortcut://<包名>/<id>`：all / start / icon / labelOf / packageOf），
  `util/WxShortcuts.kt` 改成它的薄封装（微信专属前缀 `wxshortcut://` 保留，老数据不能动）。
- `BlockType.SHORTCUT` + `HomeBlock.isShortcut` + `fromJson` 校验 + `BlockCatalog.shortcut()`。
- 渲染：`BlockCell` / `BlockRowAdapter` 加 `isShortcut` 分支（快捷方式自己的图标，读不到退宿主 App 图标）；
  管理列表类型名用新串 `block_kind_shortcut`。
- 点击：`MainActivity.performBlock` → `ActionExecutor.openShortcut()`（失败 toast `shortcut_open_failed`）；
  `ActionExecutor.openMiniProgram` 也多认一条 `shortcut://`（二级菜单/小程序列表混用时不至于走错路）。
- 「添加什么？」菜单扩到**五选一**，新增「桌面快捷方式」→ `pickShortcuts`（空列表时教用户去哪儿点）。

### 两个容易踩的点（已写进 MEMORY.md）

- 透明窗口 **不能**配 `screenOrientation`：Android 8.0 会抛
  「Only fullscreen opaque activities can request orientation」。
- 想要长辈字号缩放就得继承 `BaseActivity`(AppCompatActivity)，那主题必须换成 AppCompat 系派生的
  `Theme.Elder.Translucent`，不能用 `@android:style/Theme.Translucent.NoTitleBar`。

`assembleDebug` 通过 0 error / 0 warning，交付 **v1.0.12（构建 13）**，APK 6.4M。

## 快捷拨号点击播报联系人名称（v1.0.17 / 构建 18）

主页点快捷联系人时念名字**本来就有**，但有两个真会静音的情况，这次一并修掉：

- `TtsManager` 是异步就绪的。原来的 `speak()` 在引擎没连上时**直接把这次播报丢掉**
  （冷启动马上点联系人就听不到）；`status != SUCCESS` 时又把实例留着，
  而 `init()` 见 `tts != null` 早退 → **一次失败 = 整场会话永久静音**。
  现在：未就绪先存 `pending`，`onInit` 成功后补念；失败则 `shutdown()` + 置 null，下次点击自动重试。
  中文语音数据缺失也不再默默静音，退 `Locale.getDefault()` 并打日志。
- 顺手加了**试听播报**（`dialog_edit_quick.xml` 的 `rowQuickSpeak` + 新矢量图 `ic_volume.xml`，
  填充白、使用处 `android:tint`，同 `ic_remove` 约定）：念输入框当前内容，不用先保存。

**试听没有放在管理列表行上**：360dp 屏那一行已经「64dp 头像 + ↑ ↓ × 三个 40dp 按钮」，
文本列只剩 ~68dp，再塞一个喇叭会让号码换行，所以放进编辑弹窗（长名字改到念得顺口为止最方便）。
总开关仍是「设置 → 语音播报」，关着时点试听弹 `voice_off_hint` 指路。

另外把 MEMORY.md 又整理了一轮（去重：入口/菜单/桌面相关在三处重复的合并，补上 TTS 一节）。
本轮交付 **v1.0.17（构建 18）**，APK 6.3M。
