# 2026-10-27

## 跌倒检测（FallDetector，v1.0.37 / 构建 38）

- 新文件：`util/FallDetector.kt`（单例，进程级）、`FallActivity.kt` + `res/layout/activity_fall.xml`。
- 开关：`PrefsManager.isFallEnabled/setFallEnabled`（默认关）；管理页新卡片 `rowAdminFall`，
  预警短信**沿用「还在吗」的号码**（`AliveCenter.notifyPhone`：自定义 → SOS 兜底）。
- 检测原理（纯加速度计，无新权限）：合加速度 <3 m/s² 持续 ≥100ms（自由落体）→ 600ms 内
  ≥30 m/s² 尖峰（撞击）→ 等 2s 稳定后取低通重力方向做基准 → 偏转 >40° 算被捡起。
- 流程：撞击 → **观察 90s**（没捡起）→ 响铃（TYPE_ALARM 循环）+ 震动 + fullScreenIntent
  全屏 `FallActivity`（showWhenLocked/turnScreenOn，透明主题，**不加 screenOrientation**）→
  **再 3 分钟没回应** → 短信家人。冷却 10 分钟防连环误报。
- 关键实现点：
  - **阶段推进靠内部 Handler 循环（tickRunnable），绝不能靠页面驱动**——响铃前页面不存在。
  - 省电：只在亮屏时注册加速度计（SCREEN_ON/OFF 动态接收器）；观察期/响铃期例外（熄屏也听，
    否则永远发现不了「被捡起」）；流程结束恢复「熄屏即停」。
  - FallActivity「我没事」和**返回键**都视同机主回应（能看到页面=有回应）。
  - SEND_SMS 申请在 AdminActivity 复用 `smsPermission` launcher，靠 `smsRequestForFall` 标记
    区分回调归属（`requestEnableAlive` 里要显式清掉这个标记）。
  - Android 12+ 震动走 `VibratorManager`（VIBRATOR_SERVICE 弃用会吃 warning）。
- 构建踩坑：忘了 import `databinding.ActivityFallBinding`，报「Unresolved reference +
  Variable expected」，和 viewBinding 生成时序无关（clean 也没用），查了三轮才看到。
- 局限（对用户讲清）：掉床/沙发等软面可能测不到；进程被杀检测即停；锁屏上 TTS/页面尽量但
  各家 ROM 表现不一。
- 真机待验：传感器阈值（0g 段 100ms + 3g 尖峰）要不要按真机调；锁屏弹页各家 ROM 的成功率。

## 通话退出机制（第四轮，v1.0.43 / 构建 44）

- **通话期间静音**（顺带修掉的真问题）：ALERT 中任何电话活动（RINGING/OFFHOOK）→
  `enterCall()` 停响铃震动，家人才能听清现场；`handleAlertCycle`/`checkResponseTimeout`
  在 `inCall` 时直接 return，tick 不会把铃声拉回来、也不会在通话中发短信。
- **高级退出**：`onCallEnded()` 结算——**来电**（`incomingCall`）且接通 ≥15s
  （`CALL_EXIT_MIN_MS`，自动接听后不论谁挂断）→ 视为家人已核实，`cancelAll` 进冷却；
  太短/没接通 → 恢复提醒节奏（`alarmOn=false` 下一秒 tick 续响），`autoAnswered` 复位可再接。
- **退出只认来电**：主动拨打的升级电话 OFFHOOK 从拨号就开始，没接通也有 30s+ 的
  "通话时长"，按去电退出会把没打通的升级误判成已联系——所以去电结束只恢复、不退出。
- 退出机制全家福：①点「我没事」/返回键 ②被捡起（重力偏转 40°）③家人来电接通 ≥15s。
- 提示文案同步（fall_hint/fall_admin_on）。

## 耗电风险红字警告（第三轮，v1.0.42 / 构建 43）

- 用户担心预警响铃耗电导致关机、家人打不通反而怪软件。两处落地：
  1. 管理页跌倒卡片加**红字加粗警告块**（`fall_battery_warning`，浅红底 `fall_warn_bg`），
     说明耗电风险 + 建议保持电量充足。
  2. **预警短信带当前电量**（`fall_sms_battery`，`%3$d%%`），电量读不到时退回不带电量的
     `fall_sms`。`batteryPct` 失败返回 **-1**（不是 100），调用方按「充足」处理，读数失败不停响。
- 踩坑：布局里内联 8 位色值 `#14FFC0392B` 被 aapt2 拒（"incompatible with attribute
  background"），字符完全正常；挪到 colors.xml 资源引用就好了——**这版 AGP 对 layout 内联
  8 位 hex 颜色不可靠，以后颜色一律进 colors.xml**。

## 跌倒检测增强（第二轮，v1.0.39 / 构建 40）

用户要求：及时提醒机主、没回应就「短信+打电话」给子女、支持自动接听子女回拨、按电量调整响铃节奏。

- **观察窗 90s → 60s**（及时给机主取消误报）。
- **升级双通道**：响应超时先发短信，隔 8 秒（`CALL_DELAY_MS`）再 `ACTION_CALL` 直接拨打
  家人电话（无 CALL_PHONE 权限退 `ACTION_DIAL`）；后台拉 Activity 是尽力而为，
  被 ROM 拦时短信仍在、家人回拨走自动接听。
- **自动接听**（`phoneReceiver` 监听 `ACTION_PHONE_STATE_CHANGED`，RINGING 且处于 ALERT 才触发，
  一次流程只接一次）：
  1. 26+ 且有 `ANSWER_PHONE_CALLS`（新加 manifest + 运行时申请）→ `TelecomManager.acceptRingingCall()`
  2. 兜底：`dispatchMediaKeyEvent(KEYCODE_HEADSETHOOK)`（部分机型可用，不保证）
- **电量自适应响铃**（`handleAlertCycle`，每秒 tick 切换相位）：
  >50% 且非省电 → 持续响；21–50% 或省电 → 响 30s/停 60s；≤20% → 响 10s/停 120s。
  电量用 `BatteryManager.BATTERY_PROPERTY_CAPACITY` 现查，插上充电会自动升档。
- AdminActivity 开启跌倒检测改用 `RequestMultiplePermissions`（`fallPermissions`）一次申请
  SEND_SMS + ANSWER_PHONE_CALLS（26+ 才加后者）。
- 短信文案加了「来电会自动接听」，让家人放心拨回。
- 真机待验：acceptRingingCall 在目标 ROM 是否真放行（各厂差异大）；后台 ACTION_CALL 是否被拦。

## 电量评估（用户问「这两天加的功能耗电多少」）

- 口头分析：未接来电监听（被动）、还在吗（每小时 1 次闹钟）、远程同步（搭同一闹钟）、
  语音（用时才开）合计约 **1–2%/天**；新增跌倒检测只在亮屏时听加速度计（~0.2mA），
  观察期例外，整体仍在此量级。验证手段：系统设置→用电排行 / `adb dumpsys batterystats`。
