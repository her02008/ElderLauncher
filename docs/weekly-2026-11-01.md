### 10-26（周一）— 语音交互 + 「还在吗」+ 远程设置

| 交付 | 版本 | 说明 |
|---|---|---|
| 语音交互 | v1.0.25 / 构建 26 | 15 条封闭命令集，方言容错 |
| 「还在吗」 | 同上 | 被动活跃检测 + 短信预警 |
| 子女端远程设置 | v1.0.29 / 构建 30 | 协议先行、服务可换 |
| 远程设置 B 档 | v1.0.30 / 构建 31 | 多设备 + 修并发丢指令 |

**语音**：难点被重新定义为「识别错了还能对上」而非识别率。方案是汉字→拼音→模糊音归一化→编辑距离打分，阈值 **0.62**（正样本 0.78+，负样本 0.21~0.28，两侧余量都够）。
- 拼音库原选 `tinypinyin:2.0.3` **在 mavenCentral 拉不到**，已删依赖，改用系统自带 `android.icu.text.Transliterator`（API 24+）。**逐字转换**保音节边界，`ü` 特判成 `v`。
- `matchOne` 匹配顺序**不可改**：① 先 `extractCallName` → ② 内置命令打分 → ③ ≥0.9 直接返回 → ④ 才试「打开 X」。顺序反了「打电话给儿子」会被「打电话」抢走。
- 交互定为「点一下说，静音 1.2s 自动停」，不做按住/常驻唤醒词——老人手抖会松手，且常驻唤醒费电、方言识别差。
- 「救命」默认**直接执行**（全屏红页 + 3 秒倒计时），因为老人喊完可能没力气再点。这是刻意取舍，已写进注释防止被"优化"掉。

**「还在吗」**：不照搬「死了么」的主动签到（老人不会签），改为被动检测三源取最新：解锁 `USER_PRESENT` + 无障碍窗口变化 + App 前台。
- 定时检查用 `AlarmManager.setExactAndAllowWhileIdle`，**1 小时一次**（不用 WorkManager——Doze 下会推迟数小时到一天，24 小时预警会变 30 小时）。一次性闹钟必须自续排 + `BootReceiver` 重排。
- 预警走**短信不用推送**：老人手机没网也能发、子女不用装 App、运营商级可靠。
- **误报抑制比灵敏度重要**——必须有「暂停 1/3/7 天」（住院/出远门/手机落家），连续误报几次子女就不信告警了。

**远程设置 v1.1**：确立「协议先行、服务可换」原则。契约写在 `docs/remote-config-protocol.md`，两套服务端（Cloudflare Workers KV / Node 零依赖 JSON 文件）共用同一份 `server/admin.html`。
- 鉴权：bind 时服务端发 32 位 hex token，后续每个请求带 `X-Device`/`X-Ts`/`X-Sig = HMAC-SHA256(token, METHOD\nPATH\nTS\nBODY)`，服务端校验 5 分钟偏差。**重绑轮换 token**。
- **修了两个实质 bug**：
  1. **并发丢指令**——原来待执行指令放 `cfg:{code}.cmds` 数组，下发是「读数组 → push → 写回」，两个子女同时点按钮必然互相覆盖（Workers KV 最终一致，窗口比想象大）。改为**一条指令一个键** `cmd:{code}:{id}`。
  2. **`rev` 量级坑**——本想用毫秒时间戳防撞回旧值，但长辈端 `JSONObject.optInt` 会把 1.7e12 截断成负数，导致每次同步都重跑历史指令。改用 `秒级时间戳 - 1600000000`（约 1.9e8，2038 年也才 5.5e8）。**此坑已写进协议文档，别再改回毫秒。**
- 客户端幂等兜底：`sync()` 执行前跳过「回执队列里已有的 id」，服务端 rev 抖动或 ack 丢包重发时不会重复执行。
- **修了「绑成功了但怎么改都没反应」**：`AliveCenter.schedule()` 原只判 `isAliveEnabled`，绑了远程却没开「还在吗」的用户永远不会有第二次同步。改为两者任一成立，且关「还在吗」时调 `schedule()` 重判而非 `cancel()`。
- 指令白名单 8 条：安全 5 条（`set_font/set_voice/set_alive/set_home_order/push_msg`）+ 危险 3 条（`set_sos/set_blocks/set_quick`）。**危险指令必须长辈端弹窗确认，24 小时不处理自动作废。**

**子女端三层标识**（当晚补）：`deviceId`（UUID，仅供服务端验签名，子女端看不到）/ `code` 家庭码（服务端键前缀，同一服务端内唯一）/ 浏览器清单 `id`（UI 主键）。
- 原来的 bug：`findDevice(code)` 只比 `code`，导致「Workers 上的妈妈 8888」和「NAS 上的丈母娘 8888」互相覆盖，加第二台时表现为「妈妈那台消失了」。改用 `deviceKey(endpoint, code)` 判重，标识/切换/删除一律走 `id`。

### 10-27（周二）— 跌倒检测三轮迭代

初版 v1.0.37/构建 38 → 增强 v1.0.39/构建 40 → 耗电警告 v1.0.42/构建 43 → 通话退出 v1.0.43/构建 44。

**检测原理**（纯加速度计，**不需要任何新权限**）：
`<3 m/s²` 持续 ≥100ms（自由落体）→ 600ms 内 `≥30 m/s²` 尖峰（撞击）→ 等 2s 稳定取低通重力基准 → 偏转 >40° = 被捡起。
- **阶段推进靠内部 Handler 循环，不能靠页面驱动**——响铃前页面根本不存在。

**流程演进**：撞击 → 观察窗（90s → **60s**）→ 响铃+震动+fullScreenIntent 全屏页 → 再 3 分钟没回应 → **短信 + 隔 8s 直接拨打**子女电话（沿用「还在吗」的号码）。
- **自动接听子女回拨**：Android 26+ 且有 `ANSWER_PHONE_CALLS` → `TelecomManager.acceptRingingCall()`；兜底 `dispatchMediaKeyEvent(KEYCODE_HEADSETHOOK)`（部分机型可用，不保证）。

**电量自适应响铃**（每秒 tick 切相位，电量现查，插充电自动升档）：
>50% 持续响 ｜ 21–50% 或省电模式 响 30s/停 60s ｜ ≤20% 响 10s/停 120s

**耗电风险红字警告**（用户担心响铃耗电关机、家人打不通反怪软件）：管理页跌倒卡片加红字警告块，预警短信带上当前电量 `%3$d%%`。

**通话退出机制**（第四轮修的真实问题）：
- ALERT 中任何电话活动（RINGING/OFFHOOK）→ 静音，家人才能听清现场。
- **退出只认来电**：来电接通 ≥15s 视为家人已核实 → 退出预警进冷却；太短/没接通 → 恢复提醒节奏。
- 主动拨出的升级电话 OFFHOOK 从拨号就开始，没接通也有 30s+「通话时长」，**按去电退出会把没打通的误判成已联系**——所以去电结束只恢复、不退出。

## 四、关键结论沉淀（值得长期记住的）

**架构层**
1. **协议先行、服务可换**——短信里只放地址，长辈端只认协议（`GET /b/{code}/cfg`、`POST /b/{code}/ack`），不关心服务跑在哪。今天 Workers、明天自家 NAS + cloudflared，长辈端不用改。
2. **下发 / 落地 / 回执是三条独立链路**，只做第一条会出现「子女改完不知道生效没」。
3. **指令必须幂等**（`set_font` 是「设成某个值」不是「加一级」），重发/重试才安全。
4. **推送是死结**——个人做不了厂商推送通道，只能靠无障碍心跳拉取。
5. **下发通道 ≠ 落地通道 ≠ 回执通道**；短信单条 70 汉字，只够「地址 + 配对码 + 一条短指令」，**不能当持续通道**。绑定只需一次（手输即可），这样连 `RECEIVE_SMS` 都不用申请。

**产品层**
6. **误报抑制 > 灵敏度**——养老场景里连续误报几次，子女就不信告警了。
7. **老人喊完可能没力气再点**，所以「救命」默认执行而非二次确认。
8. **跌倒检测的退出机制只认来电**，去电误判率高。

**技术坑位**
9. `rev` **绝不能用毫秒时间戳**——`JSONObject.optInt` 会截断成负数。
10. 注释里**不要直接写带 `//` 的 URL**——Kotlin 会把 `//` 后紧跟的 `*` 当成嵌套注释开头，整份文件变注释，报的却是「Missing '}'」。
11. 这版 AGP 对 layout 内联 8 位 hex 颜色不可靠，**颜色一律进 `colors.xml`**。
12. `org.json.JSONArray` **不是 Iterable**，`queue.any { }` 编译不过，必须按 `optJSONObject(i)` 取下标。

## 五、⚠️ 发现的问题与待决策项

### P0 —— 需要 MK 拍板

**① 「恢复出厂设置」无法只清设置而保留密码（与需求有偏差）**
原始需求是「允许恢复除管理员密码外的所有设置」。当前实现只有两个选项：
- 不勾 → 只清管理密码
- 勾选 → 清密码 **+ 全部设置**（`DialActivity.confirmResetEverything()`）

根因：`PrefsManager.clearAll()` 清的是整个 `elder_prefs`，而密码盐 + 哈希（`admin_salt`/`admin_hash`）**也存在同一个 SharedPreferences 文件里**（`PrefsManager.kt:8` `PREFS = "elder_prefs"`，`AdminGate` 走 `PrefsManager.getAdminSalt/Hash`）。
→ 需要在「保留密码」与「清空一切」之间补第三个选项，或把密码迁到独立 prefs 文件。

**② 项目完全未纳入 Git 版本控制**
`0930-ElderLauncher/` 下**没有 `.git` 目录**。当前已迭代到构建 46，代码全靠手动备份，`.workbuddy/memory/` 里的 196 行 MEMORY.md 是唯一的防坑知识库。任何一次文件误操作或磁盘故障都会不可逆地丢失全部历史。
→ 建议：`git init` + 首次全量提交打 tag `v1.0.45`，之后每次构建前 commit。

### P1 —— 真机待验（代码已就绪，等硬件）

**远程设置**
- [ ] Workers 部署后从手机绑定，看 `/a/<码>` 是否显示机型、同步时间、电量
- [ ] 改字号 → 老人回桌面应自动 recreate 生效
- [ ] 改紧急联系人 → 老人端应弹「家人要改一项设置」，同意才生效、不同意不生效

- [ ] `acceptRingingCall()` 在目标 ROM 是否真放行（各厂差异大）

### P2 —— 已知局限（需告知用户，非缺陷）

- 跌倒检测：软面（床/沙发）可能测不到；进程被杀即停。
- 「恰了么」：**无障碍没开基本失效**（只剩打开桌面算活跃）。
- `HomeAction.VOICE` 在老用户机器上**不会自动出现**，需手动在功能块管理里添加。
- 微信对外链不配合：`channels.weixin.qq.com` 只在客户端内有效，外部只提示「请在微信客户端打开」。
- 桌面快捷方式固定关系按桌面应用记（`isPinnedByCaller`），换桌面/重装要重发；API 24/25 的老广播未实现。
